# Catalog Tradeskills — data rules

Runtime rules for `OneWoW_CatalogData_Tradeskills` and how they relate to
warehouse Sources under OneWoW_Workspace `.warehouse/Sources`.

## Two boxes

1. **Shipped recipes** — one OneWoW file per profession
   (`Data/Tradeskills_<Name>.lua`, global `OneWoWTradeskills_<Name>`). IDs only;
   names and icons resolve at runtime from `C_Spell` / `C_Item`. Generated by
   `python bin/tradeskill_db2_tools.py generate`.
2. **Live scan** — when this character opens a crafting table,
   `Modules/TradeskillScanner.lua` records which recipe spell IDs they know
   (`scanCache`). That cannot be shipped. Known-recipe SavedVariables stay keyed
   by English profession name and spell ID.

Do not stamp warehouse provenance on shipped rows. Live AllTheThings overlay,
if added later, may add a recipe **only if** it has a spell ID we did not ship.

## Generate

From OneWoW_Workspace, after Sources are current (`Docs/WAREHOUSE_PLAN.md`):

```bat
python bin\tradeskill_db2_tools.py generate
python bin\tradeskill_db2_tools.py status
python bin\tradeskill_db2_tools.py report
```

Pipeline:

1. **DB2** creates every playable recipe on the 14 shipped professions
   (Alchemy through Tailoring, plus Housing Dyes). Archaeology is not shipped.
2. **Warehouse Sources** fill **empty** learn-source
   fields only (`quest`, `npc`, `taught`, `map`, `xy`, `cost`, then `learn`).
   Never overwrite a set field. Unobtainable flags in a source shelf do not
   delete a DB2 row.
3. **Wowhead** leftover fill is a separate CLI
   (`python bin/wowhead/profession-spells.py`). Not part of generate. See
   **Wowhead leftover fill** below. One expansion at a time, newest first.

Skip SpellName matching DNT / NYI / UNUSED / `[PH]` / TEST. Skip each
profession's SpellBookSpellID (the "learn this profession" spell). Do not invent
recipe IDs from warehouse shelves or Wowhead leftover fill.

## Record fields

Public fields consumers already read: `id`, `item`, `icon`, `cat`, `prof`,
`exp`, `rg`, `sl`, `prev`, `next`, `qual`, `maxQ`.

Also shipped when present: `pid`, `min`, `lo`, `hi`, `items`, `taught`,
`learn`, `npc`, `quest`, `map`, `xy`, `cost`, `fcq`, `mask`.

`prof` is the English identifier (`Alchemy`, `HousingDyes`, …), not a localized
display string. `exp` keys match the existing expansion table in
`Modules/TradeskillData.lua`. `rg` is `{itemID, qty, required}` with required
`1` or `0`.

Dropped: `link` (locale-baked item links).

## Compat

Do not re-key `scanCache` to skill-line ID without a SavedVariables migration.
Item Search and other suite units must read
`OneWoW_CatalogData_Tradeskills_API`, not `_G["OneWoWTradeskills_"..]`.

## Reagents and outputs

Classic reagents come from `SpellReagents`. Dragonflight+ reagents come from
`ModifiedCraftingSpellSlot` joined by slot name to `CraftingReagentQuality`
items. Optional slots are `ReagentType >= 2` (or Flags bit 2). `sl` is emitted
when a slot is optional or has more than one item ID.

Outputs: SpellEffect 24 `EffectItemType`, or effect 288 → `CraftingData` /
`CraftingDataItemQuality` (`item` plus `items` when there are quality siblings).

## Learn sources

`learn` is `trainer` / `quest` / `item` / `drop` / `vendor` / `auto` / `spec`
when known.

`spec` is Dragonflight+ profession specializations. Stamp only when
`TraitDefinition` text teaches that recipe (`Learn to craft`, `Learn $@spellname`,
`Teaches you the recipe`). Do not stamp every trait node that names a spell
(those are often stat perks on an already-known craft). Spec runs from DB2
before warehouse / leftover fill so a later trainer guess cannot replace it.

AcquireMethod `1` falls back to trainer and `2` to item. AcquireMethod `0` is
unspecified in current DB2 — do not stamp Automatic from skill rank (`min` /
`lo` / `hi` are craft difficulty, not a learn source).
`taught` is the recipe scroll item when DB2 or warehouse Sources can map it. Catalog details
prefer `recipe.taught` over a live profession-window lookup.

## Wowhead leftover fill (backwards)

Pull **one expansion at a time**, newest unfinished first, down to Classic.
Do not start the next expansion until the current one has parse +
`python bin/tradeskill_db2_tools.py generate`.

overwrite a set `learn` / `npc` / `quest` / `taught` / `map` / `xy` / `cost`.

From OneWoW_Workspace:

```bat
python bin\wowhead\profession-spells.py run
```

`run` is TWW → Classic, 1.8s between live pages. Fetch + parse + generate per
expansion. Rate-limit: wait 180s and resume the same expansion. `status` writes hole-id lists (from shipped Lua, not Wowhead) to
`.warehouse/Sources/WowHead/professions/holes/{Expansion}.json`. HTML/JSON
caches stay gitignored under `.warehouse/Sources/WowHead/professions/`.
